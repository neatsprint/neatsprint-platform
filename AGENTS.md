# AGENTS.md — NeatSprint Engineering Guide for AI Agents

> **Status**: Active · **Owner**: Laksiri (Project Owner) / OpenCade (AI) · **Last updated**: 2026-11-21

This file is the operating manual for any AI agent (OpenCode, Claude Code, or other) working in
this repository. Read it **before** reading any other document. If this file conflicts with a
document in `docs/`, `docs/` wins for product detail and this file wins for process.

## 1. What We Are Building

**NeatSprint** is a Commercial Open Source, multi-tenant, agile task-management and
privacy-first work-monitoring platform. It ships as:

| Client | Purpose |
| :--- | :--- |
| **Web app** | Management console: projects, sprints, reports, admin, monitoring review |
| **Desktop agent** | Primary work interface: timer, idle detection, screenshots, offline sync |
| **Mobile app** | On-the-go: assigned work, manual time, chat, notifications |

It is delivered as **microservices** behind a single **API gateway**, orchestrated with
**Docker Compose** in development and Kubernetes in production.

## 3. Hard Rules

These are never optional.

1. **Tenant isolation** — every tenant-owned row carries `tenant_id`; every query is scoped by
   the authenticated tenant. Cross-tenant reads are a P0 defect.
2. **Privacy window** — a user's screenshot can be deleted inside the configured window; once
   deleted, pixel data and AI embeddings are irreversibly destroyed. Managers see a tombstone,
   never the image.
3. **RBAC enforcement server-side** — the UI may hide controls, but the API must deny.
   Permissions use `domain:resource:action` (e.g. `task:item:create`).
4. **IDs are UUIDv7** generated by the client for offline-capable entities, never sequential.
5. **No cross-service database access** — services talk over HTTP/events only.
6. **Secrets never in git** — `.env` is ignored; `.env.example` documents variables.
7. **No feature is "done"** until: code + tests + docs + checklist tick + changelog entry.
8. **Every UI string is intentional** — use the copy in `docs/UI_UX_DESIGN.md`; no lorem ipsum.

## 4. Working Agreement With Laksiri

- New work arrives as a `# Human Message: <yyyyMMddhhmmss>` block appended to
  `agent/conversation.md`, triggered by the word `attend`.
- Respond with `# AI Message: <yyyyMMddhhmmss>` **appended below** the human message, and
  **appended at the bottom** of `agent/conversation.md`. Never rewrite earlier turns.
- The response must state: what was done, what was decided, what is blocked, and what is next.
- **Ask before blocking decisions** that change scope, cost, licensing, or vendor choice.
  Record the answer in `docs/DECISIONS.md`.
- Work **step by step**. Finish and verify one milestone/task before starting the next.
- **Before starting a new task, commit and push the previous task's work** (rule 11 of the
  project brief). Use a meaningful Conventional Commit message.
- Tick checkboxes (`[ ]` → `[x]`) as work completes. Never pre-tick planned work.

## 6. Canonical Technology Choices

| Layer | Choice | Notes |
| :--- | :--- | :--- |
| Backend services | **Python 3.12 + FastAPI**, Pydantic v2, SQLAlchemy 2 (async), Alembic | One service = one logical database |
| Dependency tool | **uv** | `uv.lock` committed |
| Web | **Next.js 15 (App Router) + TypeScript**, Tailwind CSS, shadcn/ui, TanStack Query, Zustand | Node 22 LTS |
| Desktop | **Tauri v2 + Rust + React/TS**, SQLCipher | Windows/macOS/Linux |
| Mobile | **React Native (Expo) + TypeScript** | Phase 2 |
| Gateway | **Traefik v3** | ForwardAuth to IAM |
| Data | **PostgreSQL 16** (per-service logical DB, `pgvector` for AI), **Redis 7**, **MinIO/S3** | |
| Events | **Redis Streams + transactional outbox** (MVP); Kafka only if scale demands | |
| Observability | OpenTelemetry, Prometheus, Grafana, Loki | |
| CI/CD | GitHub Actions; images to GHCR; Argo CD + Helm for k8s (Phase 2+) | |

Deviations require an ADR in `docs/DECISIONS.md`.

**Runtime boundaries (ADR-018)**: domain services are Python/FastAPI; Next.js is only the web UI +
thin BFF; Rust is reserved for CPU-bound, memory-constrained or endpoint-resident components (the
desktop agent today, a media worker if the M3 benchmark demands it). Exhaust `libvips`, DB
aggregation and worker parallelism before introducing Rust. Never rewrite a CRUD service in Rust.

## 7. Coding Standards (summary)

- **Python**: Ruff (lint + format), mypy strict on `src/`, `pytest` + `pytest-asyncio`,
  dependency injection over globals, no business logic in routers, repositories own SQL.
- **TypeScript**: ESLint + Prettier, `strict: true`, no `any` without a comment, generated API
  types from OpenAPI (never hand-write request/response shapes).
- **API**: OpenAPI 3.1 is generated by the code and published to `neatsprint-contracts`;
  breaking changes require a version bump and an ADR.
- **DB**: forward-only Alembic migrations, snake_case, `created_at/updated_at/created_by/updated_by`
  on all business tables, soft delete via `deleted_at`.
- **Errors**: RFC 7807 problem details, stable machine-readable `code`.
- **Logs**: structured JSON, no PII, never log tokens or screenshot contents.
- **Tests**: unit + integration per service; contract tests against OpenAPI; Playwright E2E for
  critical journeys; every bug fix ships with a regression test.

## 8. Definition of Done

A task is done only when all of the following are true:

- [ ] Acceptance criteria in `docs/DEVELOPMENT_PLAN.md` are met
- [ ] Unit and integration tests pass locally and in CI
- [ ] Lint, type-check and secret scan pass
- [ ] OpenAPI/event contract updated if the interface changed
- [ ] Migration added and reversible-by-forward-fix if schema changed
- [ ] Security review for authz-relevant code (tenant scope + permission check present)
- [ ] Docs updated (`docs/`), checkbox ticked, changelog/`docs/CHANGELOG.md` updated
- [ ] Commit pushed with Conventional Commit message referencing the task ID

## 9. Agent Operating Loop

1. **Orient** — read the last human message, then the plan checkboxes to find the next unchecked
   task in the active milestone.
2. **Confirm** — if a decision is ambiguous or costly, ask; otherwise proceed with the documented
   default and note the assumption.
3. **Plan** — list files to create/change and tests to add (short, in the response).
4. **Execute** — small, coherent commits. Prefer working vertical slices over broad stubs.
5. **Verify** — run linters/tests; if the environment cannot run them, say so explicitly.
6. **Record** — tick checkboxes, update `docs/DECISIONS.md` for choices, write the AI message.
7. **Ship** — commit and push before moving to the next task.

### Things an agent must never do

- Delete or rewrite `documents/` (reference) or earlier conversation turns.
- Commit secrets, credentials, customer data, or generated binaries.
- Change submodule remotes, licenses, or the AGPLv3 terms without instruction.
- Mark a task complete without evidence (test run, screenshot, or explicit note).
- Implement Phase 2/3 features during MVP hardening.

## 10. Quick Commands (once scaffolding lands in M0)

```bash
docker compose up -d --build          # full local stack
docker compose logs -f gateway        # tail edge logs
make bootstrap                        # create .env from example, install hooks
make migrate                          # run all service migrations
make seed                             # demo tenant, users, project, tasks
make test                             # unit + integration across services
make e2e                              # Playwright critical journeys
make lint                             # ruff, eslint, tsc, hadolint
make down                             # stop stack, keep volumes
```
